# Pull Requests

Pull Requests are a way to allow users to review and request as needed in a seperate branch before merging a file, folder, code, or
program into the main branch. This is helpful because everyone can agree on the final result and merge it to the main branch in
one single go. Since the `Code` tab in GitHub represents the final result and the `Issues` tab represents reported problems, then
the `Pull Requests` tab can be thought of as the construction site, where everyone collaborates and makes improvements until the
work is ready to be published in the `Code` tab. This means that if you have not created a seperate branch to serve as the 
"construction site", you should create one before making a Pull Request. This allows you to make and review changes without
directly modifying the final main branch.
  
## Creating A Pull Request

Under the `Pull Request` tab, find and click on the green `New pull request` button.
  
 > Insert Image
  
Then, set the `base` branch to your desired target branch and the `compare` branch to your current working branch. In other words, 
the `compare` branch is your construction site, where you made your changes, and the `base` branch is where you want to publish 
the final result. After that, click the green `Create Pull Request` button to create the pull request.
  
 > Insert Image
  
Once you have that all set and done, you can now create the title and description of your pull request. Ensure to follow good
practices and once you are ready, click the green `Create pull request`.

## Linking Pull Request To Issue

Finally, to ensure that your Pull Request is working on the correct Issue, it will need to be linked together. Simply go to the 
`Development` tab and click on the desired issue to link your PR to it.
