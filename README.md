# Welcome To GitHub-Guide

A personal and collaborative reference guide for **Git, GitHub, and software development workflows**. This repository is our own version of a GitHub textbook. It'll include a collection of notes, guides, examples, commands, workflows, and best practices that I've learned along the way. The goal is to document everything we learn about GitHub to this repository for use as a quick refresher and giving collaborators a shared reference to use when working together on other repositories.
  
## What's Inside

This repository covers topics such as:

 - Pull requests
 - Issues and project tracking
 - Code reviews
 - Merge conflicts
 - Git commands and workflows
 - Repository organization
 - GitHub best practices

## Purpose

The purpose of this repository is to create a **quick and reliable reference** for us and those we work with. Instead of having to search through old projects, documentation, tutorials, or random notes every time we forget something, we can use this repository as a centralized reference. The guides are written in a way that focuses on:

  
 - **What something does**
 - **Why it is used**
 - **How to use it**
 - **Examples**
 - **Common mistakes**
 - **Best practices**
  
## How We Use This Repository

This repository is meant to grow over time. When we learn something useful about Git, GitHub, or a development workflow, we can add it here so we don't have to relearn it later. When working on another project, this repository can also be used as a reference for keeping our workflow consistent. For example:
  
```text
I forget how to create a branch
        ↓
Check the Branches guide
        ↓
Find the command + explanation + example
        ↓
Continue working
```
  
## For Collaborators

This guide can also serve as a shared reference when working with other developers. The goal isn't necessarily to enforce every rule in every project. Different repositories may have different requirements. Instead, this repository provides a **baseline of recommended practices** that we can refer to when deciding how we want to organize and manage a project. Project-specific rules should always take priority when they differ from this guide.
  
## Work in Progress

This repository is a **living reference** and is expected to change as we learn more. Some guides may be incomplete, simplified, or based from our own experience. Due to this, it is advised not to use this as an official guide and always refer to GitHubs actual references.
